# Information Searcher: Агентский аналитический движок по нозологиям (Кейс №1: Контрактура Дюпюитрена 2016–2026)

## What This Is

Универсальный исследовательский конвейер на Python + SQLite + мультиагентной экстракции, который собирает доступную мировую научную литературу из PubMed, Europe PMC, OpenAlex и ClinicalTrials.gov по заданной нозологии, проводит PRISMA-скрининг и ранжирование по уровню доказательности, извлекает структурированные клинические и молекулярные данные в локальную БД и формирует аналитические отчеты в трех форматах (диссертационная монография, краткое резюме, внутренняя база знаний). Первая целевая реализация — полный анализ литературы по контрактуре Дюпюитрена за последние 10 лет (2016–2026 гг.): этиология, патогенез, консервативные и хирургические подходы, отдаленные результаты и рецидивы.

## Core Value

Доказательный, верифицируемый по PMID/DOI синтез клинической и фундаментальной литературы за 10 лет без галлюцинаций, канцелярита и ИИ-штампов, опирающийся на структурированную базу извлеченных данных, а не на слепой RAG-поиск.

## Requirements

### Validated

- ✓ Локальная установка фреймворка GSD v1.42.3 (`get-shit-done-cc`) под среду Antigravity — Phase 0
- ✓ Создание скилла `ru-medical-humanizer` (правила де-ИИзации русского медицинского текста и спецификация 3 форматов вывода) — Phase 0
- ✓ Создание скилла `nosology-research-pipeline` и базовой SQLite-схемы (`src/schema.py`, `configs/dupuytren.yaml`) — Phase 0

### Active

- [ ] Полная выгрузка корпуса литературы за 2016–2026 гг. по контрактуре Дюпюитрена из PubMed, Europe PMC, OpenAlex и ClinicalTrials.gov
- [ ] Дедупликация, PRISMA-фильтрация, стратификация по уровням доказательности (`Tier 1–4`) и докачка открытых полнотекстовых XML из Europe PMC
- [ ] Параллельная агентская экстракция данных в таблицы БД по 4 блокам (этиология/генетика, молекулярный патогенез, малоинвазивное/консервативное лечение, хирургическое лечение и отдаленные рецидивы)
- [ ] Генерация отчета в 3 вариантах: (1) научная работа диссертационного уровня, (2) краткое содержание, (3) внутренняя база знаний
- [ ] Интерактивный веб-интерфейс (Streamlit) для переключения режимов отчета, фильтрации базы из ~3000 статей и запуска пайплайна под новые нозологии

### Out of Scope

- Нелегальный обход пейволлов закрытых издательств (Elsevier/Wiley/Springer) — используются только официальные API (NCBI E-utilities, Europe PMC Open Access XML, OpenAlex, ClinicalTrials.gov) и полные метаданные/абстракты для закрытых статей.
- Классический «сырой» векторный чат-бот поверх неразмеченных PDF без предварительной табличной экстракции — приводит к потере статистической точности при сравнении клинических исходов.

## Context

- Среда разработки: Windows, PowerShell, Python (`uv` 0.13.7), Node.js (для `gsd-tools.cjs`), встроенные научные скиллы плагина `science` (`pubmed-database`, `literature-search-europepmc`, `literature-search-openalex`, `clinical-trials-database`).
- Объем выборки по контрактуре Дюпюитрена за 2016–2026 гг.: ожидается 2 500 – 3 500 уникальных записей.

## Constraints

- **Стиль языка**: Строгое соблюдение правил `ru-medical-humanizer` как в текстах отчетов, так и в рабочем диалоге (никаких шаблонных вступлений, комплиментов и воды).
- **Трассируемость фактов**: Каждое численное утверждение (частота рецидивов, отношение шансов GWAS, осложнения) в отчете должно ссылаться на конкретный `PMID` / `DOI` / `NCT ID` из локальной базы `data/dupuytren/literature.db`.
- **Универсальность кода**: Скрипты сбора, триажа и витрины не должны содержать захардкоженных строк под Дюпюитрена — все параметры нозологии читаются из `configs/<nosology>.yaml`.

## Key Decisions

| Decision | Rationale | Outcome |
|----------|-----------|---------|
| PRISMA-триаж + табличная Map-Reduce экстракция вместо обычного RAG | Обычный RAG не способен агрегировать частоты рецидивов и осложнений по десяткам РКИ и когорт | ✓ Good |
| Python + SQLite + Streamlit вместо тяжелого фронтенда/бэкенда с нуля | Позволяет быстро получить проверяемую базу данных, отчеты и интерактивный дашборд | ✓ Good |
| Поддержка 3 режимов отчета (`dissertation`, `summary`, `knowledge_base`) | Закрывает потребности и для глубокой диссертационной работы, и для быстрой клинической справки | ✓ Good |
| Переход на фреймворк GSD (`.planning/`) | Защищает от деградации контекста при работе с большим корпусом литературы и делит проект на проверяемые фазы | ✓ Good |
