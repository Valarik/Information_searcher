# Phase 1: Сбор корпуса и PRISMA-триаж - Context

**Gathered:** 2026-11-04
**Status:** Ready for execution

<domain>
## Phase Boundary

Собрать полный дедуплицированный корпус публикаций и клинических исследований по контрактуре Дюпюитрена за 2016–2026 гг. из 4 официальных источников (PubMed, Europe PMC, OpenAlex, ClinicalTrials.gov) в локальную базу данных SQLite (`data/dupuytren/literature.db`), провести автоматический PRISMA-скрининг, ранжирование по уровням доказательности (`Tier 1–4`), разметку по 5 тематическим кластерам и выгрузку полнотекстовых XML для открытых статей. Глубокая экстракция таблиц субагентами и генерация текстов отчетов относятся к Фазам 2 и 3.

</domain>

<decisions>
## Implementation Decisions

### Языковой фильтр и границы включения
- **D-01 (Языки):** Сохранять публикации на любых языках (включая немецкую и французскую школы хирургии кисти), если у статьи присутствует абстракт на английском или русском языке. Статьи на иных языках без переведенного абстракта исключать из аналитической выборки.
- **D-02 (Препринты):** Включать препринты за 2023–2026 гг. (bioRxiv / medRxiv / ResearchSquare через Europe PMC и OpenAlex) с явной меткой `[Preprint]`, если они ещё не вышли в рецензируемом журнале (при наличии журнальной версии склеивать в пользу журнальной статьи). Это позволяет не потерять свежие работы по scRNA-seq и пространственной транскриптомике.
- **D-03 (Смежные фиброматозы):** Работы по болезни Леддерхозе (подошвенный фиброматоз), болезни Пейрони и подушечкам Гаррода оставлять только в том случае, если в них явно исследуется связь с болезнью Дюпюитрена (диатез Дюпюитрена, общие локусы GWAS/Wnt-путь). Изолированные статьи по Пейрони или Леддерхозе отсекать.
- **D-04 (Жесткий фильтр нецелевых совпадений):** Автоматически отсекать в `src/triage.py` эпонимический перелом Дюпюитрена (перелом лодыжки / нижней трети голени: `ankle fracture`, `malleolar`, `fibula`, `tibiofibular`) и общие статьи по хирургии кисти, где контрактура Дюпюитрена не является предметом исследования.

### Политика работы с Tier 4 и стратификация доказательности
- **D-05 (Хранение и роль Tier 4):** Одиночные клинические случаи (case reports), письма в редакцию, комментарии и тезисы без данных не удалять физически, а сохранять в таблице `articles` с меткой `evidence_tier = 4`. Они учитываются в PRISMA-статистике и используются в отдельном фильтре редких казуистических осложнений (например, ишемический некроз пальца, разрыв сухожилия после коллагеназы, псевдоаневризма), но строго исключаются из расчета средних частот эффективности и рецидивов.
- **D-06 (Разделение обзоров):** Систематические обзоры и метаанализы относить к `Tier 1`. Обычные нарративные обзоры (Narrative Reviews без систематического протокола и метаанализа) относить к `Tier 3` и использовать только для перекрестной проверки полноты библиографии, а количественные показатели (рецидивы, осложнения, коррекция контрактуры) извлекать из первичных РКИ и когорт во избежание двойного счета.

### Глубина выгрузки полных текстов (Europe PMC XML)
- **D-07 (Охват Full-Text XML):** Скачивать открытые полнотекстовые XML из Europe PMC для всех оригинальных исследований, когорт, РКИ, метаанализов и обзоров уровней `Tier 1–3` (ожидаемо ~600–900 статей), пропуская только `Tier 4` (case reports, письма, комментарии).

### Режим запросов к API и лимиты
- **D-08 (Безключевой запуск с пакетным троттлингом):** Запускать `src/harvester.py` в безключевом режиме со встроенным контролем частоты запросов (3 запроса/с для PubMed с пакетной выгрузкой по 200 PMID за запрос, 1 запрос/с для Europe PMC с пагинацией по 1000 записей, пагинация по 100 записей для OpenAlex и ClinicalTrials.gov) и автоматическим экспоненциальным повтором при коде 429.

</decisions>
